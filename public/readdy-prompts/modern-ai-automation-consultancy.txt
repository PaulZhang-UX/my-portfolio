1. 设计基础 Prompt
============================================================

Create a frontend design system for a B2B consultancy website named “methodic”, focused on AI automation and implementation for growing businesses.

Use an editorial operations-system visual language: an almost-white paper canvas, cool gray structural rules, a restrained Signal Blue accent, small uppercase monospace labels, light-weight IBM Plex Sans headlines, and IBM Plex Mono metadata. The page should feel precise, calm, technical, and human-controlled rather than like a generic SaaS dashboard.

Use these source-aligned colors:
- White paper background: oklch(1 0 0)
- Soft cool-gray surfaces: background neutral values around oklch(0.966 0 0) and oklch(0.912 0 0)
- Dark text: oklch(0.2 0 0)
- Muted text: oklch(0.4 0 0) to oklch(0.53 0 0)
- Primary Signal Blue: #0F62FE, with lighter blue tints for rules and surfaces
- Verified state green: #168B61
- Technical diagram grays: #A0ABBB, #8E9AAC, and #D0D8E3

Use IBM Plex Sans for headings and body copy. Use IBM Plex Mono for section indices, system labels, event traces, status readouts, and metadata. Headlines are light, compact, and slightly tight in tracking. Labels are uppercase with generous letter spacing.

Build layouts around a centered 1440px frame with responsive horizontal padding of approximately 20px, 40px, and 80px. Add two persistent vertical rails and full-width chapter rules. Use generous whitespace, border-separated rows, square controls, and rectangular CTAs. Avoid rounded cards, heavy shadows, decorative stock imagery, and excessive gradients.

Visualize workflow concepts with thin SVG diagrams, procedural line drawings, state dots, path traces, and restrained Canvas motion. Blue indicates active routing or brand emphasis. Green indicates verified or completed states. Every animation must have a readable resting state and a prefers-reduced-motion fallback.

The responsive system must preserve the information hierarchy. Stack editorial and interactive system columns below tablet widths, convert wide diagrams into readable mobile maps or vertical node lists, and replace desktop navigation with a compact menu.

You are rebuilding a frontend-only website called “methodic” for an AI automation and implementation consultancy serving growing businesses.

The goal is to reproduce the supplied website’s information architecture, visual system, layout rhythm, interaction states, and motion behavior. Do not redesign the product, add a backend database, or introduce a different visual direction. Treat the instructions below as the source of truth for the reconstruction.

## Project Definition

Build a responsive React website with client-side routing and static/mock content. The site explains how methodic redesigns operational workflows and connects AI to the systems a team already uses.

Use these routes:
- `/` — the full Home page.
- `/services`, `/approach`, and `/outcomes` — render the Home page and position the viewport at the matching Home section. Use plain paths as the navigation contract; do not depend on hash-only navigation.
- `/contact` — the Contact page with a consultation form.
- `/services/customer-operations` — the Customer Operations detail page.
- `/services/finance-operations` — the Finance Operations detail page.
- `/services/sales-operations` — the Sales Operations detail page.
- `/services/internal-workflows` — the Internal Workflows detail page.
- Any unknown route — a simple 404 page.

The site is frontend-only. Use static data objects for page copy. Keep the form receiver configurable and do not create a database or invented server-side workflow.

## Global Visual Direction

Create an editorial operations-system aesthetic:
- Almost-white paper background with cool neutral gray surfaces.
- Signal Blue as the primary brand accent and CTA color.
- Thin gray and pale-blue structural rules.
- Light, precise typography with large quiet headlines.
- Uppercase monospace labels, numbered chapters, status dots, workflow traces, and technical diagram annotations.
- A calm, controlled, human-in-the-loop feeling.

Do not use stock photography, image-heavy hero artwork, rounded SaaS cards, large shadows, glossy gradients, or a generic dashboard appearance. The main visual assets are procedural Canvas and SVG diagrams, fine rules, framed sections, and restrained state changes.

## Design System

Use IBM Plex Sans for headings and body copy. Use IBM Plex Mono for labels, section indices, system metadata, event readouts, and status values. Headings are mostly weight 300 with compact line-height around 1.06–1.1. Body copy is light and relaxed around 1.5–1.6. Labels are uppercase with letter spacing around 0.1–0.18em.

Use these source-aligned colors:
- Paper background: white, source token `oklch(1 0 0)`.
- Light neutral surfaces: source background values around `oklch(0.966 0 0)` and `oklch(0.912 0 0)`.
- Primary text: source foreground value around `oklch(0.2 0 0)`.
- Muted text: source foreground values around `oklch(0.4 0 0)` to `oklch(0.53 0 0)`.
- Signal Blue: `#0F62FE`, with pale blue tints for backgrounds and rules.
- Verified green: `#168B61`.
- Diagram gray strokes: `#A0ABBB`, `#8E9AAC`, and `#D0D8E3`.

Build the page inside a centered outer frame with a maximum width of about 1440px and responsive horizontal padding of approximately 20px, 40px, and 80px. Add two permanent vertical rails aligned to this frame. Each major chapter has a top and bottom full-width rule with empty breathing space between chapters.

Use square or minimally softened controls, border-separated rows, thin underlines, and rectangular buttons. A primary button is filled Signal Blue with white text and a right arrow. A light button is white with blue text. Hover states are quiet but clearly visible.

## Website Information Architecture

The global Header is positioned at the top of the page frame. On desktop, show the `methodic /` wordmark, links for Services, Approach, and Outcomes, and a “Discuss a Workflow →” CTA. ## Interaction and Motion Rules

Implement the following global behavior:
- Page fade-in around 320ms ease-out on route changes, with Home section routes sharing one fade key.
- Chapter top rules draw over about 1100ms with a strong ease-out; bottom rules start about 180ms later.
- Outer rails drop from top to bottom over about 1800ms.
- Plain text links grow a 1px underline over about 260ms.
- CTA arrows nudge right by about 4px over roughly 220ms.
- Global keyboard focus uses a visible blue 2px outline with a small offset.
- Use a custom four-corner target cursor only on fine pointers. Hide the native cursor over target elements, lock the frame to target bounds, rotate slowly while idle, and disable it on touch/coarse pointers or reduced motion.

Every animation must fail open: the resting UI must remain visible if IntersectionObserver, animation-timeline, Canvas, or a motion preference branch is unavailable.

## Technical Requirements

- Use componentized shared layout primitives for the frame, rules, header, section labels, links, and service template.
- Use static data objects for page copy.
- Use SVG and Canvas only where necessary for the supplied diagrams.
- Clean up requestAnimationFrame loops, observers, event listeners, and generated SVG nodes on unmount.
- Pause visible-loop animations when their panel is offscreen or the document is hidden.
- Keep all external font, icon, and form endpoints configurable.
- Do not add a database, authentication, CMS, payment flow, or unrelated third-party service.

## Quality Assurance

Verify:
1. Every route resolves to the correct page.
2. `/services`, `/approach`, and `/outcomes` reach the correct Home section after navigation.
3. The Header, rails, chapter rules, section numbering, typography, and color hierarchy remain consistent.
4. All major Section orders match the specification above.
5. Each interactive system updates both the diagram and its textual readout without reporting a future state early.
6. Reduced-motion mode shows a stable readable state and does not leave the page hidden.
7. Mobile layouts do not clip essential labels, controls, or form errors.
8. Canvas, SVG, observer, and timer resources are cleaned up when components unmount.
9. The Contact form has complete required-field validation and clear loading, error, and success states.
10. No stock images, unrequested redesigns, database schema, or unrelated integrations are introduced.

## Explicit Constraints and Avoidances

- Reproduce the existing visual direction; do not modernize it into a different design system.
- Do not replace technical diagrams with generic icons or stock illustrations.
- Do not collapse all motion into one generic “smooth animation”. Preserve triggers, states, sequence, and timing where specified.
- Do not treat dormant files or unused package dependencies as active page requirements.
- Do not claim that a procedural effect is pixel-perfect if the original algorithm is unavailable.
- Do not modify the existing source project while analyzing or documenting it.
